# dsh-history-plugin 实现方案（交付 DSH）

## 1. 目标与边界

用户在旧设备安装过 DSH 插件后，新设备授权**同一个百度网盘账号**，即可自动看到历史列表，勾选若干插件并确认批量重新安装。DeepSeek 账号不参与身份识别、授权或同步；网盘授权本身决定能访问哪份历史。

本方案交付范围仅同步**插件安装历史**，包括安装时间和设备 ID。不上传插件包、配置、密钥、对话或设备运行状态；不跨设备自动安装。已卸载的插件仍保留在历史中。历史的含义是“曾成功安装”，不是“现在已安装”。之前文档里的“第一版”只是阶段称呼，并非要删掉这些需求；此处直接写成完整交付范围。

## 2. 选型与前提

| 层 | 选择 | 说明 |
| --- | --- | --- |
| DSH 插件 | npm bundle，包名 `dsh-history-plugin` | `package.json` 声明 `dsh.bundle.patch`；Host 服务处理账号、记录和同步，Client 展示历史与安装进度。 |
| 安装事实 | DSH plugin-manager 服务 | 监听 `plugin-manager/changed` 后调用 `listBundles` 重新核对；启动时做一次扫描，补录安装本插件之前的现存外部 bundle。只记录 `installed=true` 的 profile 依赖，排除预装、仅启用的官方项、本插件自身。 |
| 账号 | 百度网盘 OAuth | 同一个网盘账号即同一份历史。无需 DeepSeek 登录或账号 ID。授权成功后可读取百度用户 ID，供本地缓存隔离和设置页展示；不把账号 ID 写入历史 JSON。 |
| 存储 | 用户自己的百度网盘 | 不租服务器。默认在网盘最外层建立 `/dsh-history-plugin/` 文件夹；用户可在设置中指定其他有读写权限的网盘文件夹。不同百度网盘账号天然隔离。 |
| 百度授权 | 正式发布优先使用自己的百度开放平台应用与 OAuth 授权码/设备码流程；零注册体验由插件自有的 Desktop guest browser 读回演示应用成功页 | 演示应用只用于限时体验，不作为产品凭据。DSH Desktop 由 Client 在插件自己持有的 guest webview 中打开百度授权页，读取该页面的成功地址并把原文交给 Host；Host 校验 `state` 后保存 token。非 Desktop 或桥不可用时回退到一次性剪贴板读取。令牌及刷新令牌存 Host 安全凭据存储；Client 不解析、不持久化、不回显。到期刷新，失效时提示重新授权。 |
| 网盘访问 | 百度网盘 MCP 上传；百度网盘开放 API 下载 | 已实测 `file_upload_by_content` 可写 JSON。当前 MCP 的 `file_meta` 不能返回 JSON 正文，也没有可靠的原文下载工具；读取采用 `filemetas(dlink=1)` 后流式下载到本机临时文件。MCP 文本上传有长度限制，且重复文件的覆盖行为须验证；超过限制或不能可靠覆盖时使用百度开放 API 上传。封装 `BaiduHistoryStore`，避免上层依赖具体传输方式。 |

**授权来源说明：**先前的单机读写测试没有自动注册百度应用，也没有使用已证实由 OpenAI 注册的应用；测试是沿百度网盘官方 MCP 文档的“个人用户限时体验”入口取得用户授权，再以该 access token 访问 MCP 和开放 API。百度官方明确称体验密钥仅供测试、会变更，不能作为正式产品凭据。正式发布需要由插件项目方确定自己的百度开放平台应用/获准的正式接入方式；不能要求每个普通用户都注册开发者应用，也不能把 SecretKey 明文打包进客户端。具体 OAuth 客户端形态和是否需要服务端保管密钥须在百度开放平台条件下确认。

**当前零注册实现形态：**DSH Desktop 的 browser bridge 协议版本 1 允许插件申请一个归插件所有的 guest webview 分区。Client 在设置页内打开百度授权页，授权面板是设置弹窗里最上层的独立模态（层级高于设置遮罩，Escape/Tab 归它），登录页可见、可点。Client 只监听这一个 webview 的导航和 `getURL()`；命中百度 `login_success#access_token=…` 后，把整条地址和本次 `state` 交给 Host；加载失败或迟迟没有可用导航则回退到剪贴板路径。它不读取其他浏览器标签、Cookie、MCP 配置或后台剪贴板。非 Desktop 宿主或 bridge 版本不匹配时，才回退到“用户显式复制一次成功页地址，窗口获得焦点/恢复可见后读剪贴板”的兼容路径。两条路径都由 Host 负责 `state` 校验、token 提取和持久化。

**集成约束：** DSH 插件代码运行在 Host；plugin-manager 服务和客户端入口的具体依赖注入名称、权限和可用性，应以目标 DSH 版本源码核对。若某服务不对第三方 bundle 开放，先添加最小公共适配接口，不读取私有配置文件或模拟 UI 点击。

### 启动时发现已有登录凭据

启动后自动检查本插件以前保存在 Host 安全凭据存储中的百度授权：有可用 access token 就验证用户身份并同步；过期且有 refresh token 就先刷新再同步。若 DSH 提供**正式的共享百度网盘授权接口**，可通过该接口复用已授权连接；这需要目标 DSH 版本确认。检测到电脑已登录百度网盘客户端或浏览器，不等于插件可以直接取得 API 凭据；不扫描浏览器 Cookie、其他应用的 token 文件或 MCP 配置中的密钥。没有可复用的授权时，在设置页显示“连接百度网盘”，打开百度 OAuth 授权；浏览器已有登录会话时通常可减少重新输入账号的步骤，但仍按百度的授权流程完成连接。若只发现一个已连接的 MCP 而无法通过受支持接口取得下载 API 所需授权，也显示连接按钮，不假称已具备完整同步能力。

## 3. 云文件布局和记录格式

默认在网盘**最外层**建立 `/dsh-history-plugin/` 文件夹，历史文件放在 `/dsh-history-plugin/v1/replicas/<deviceId>.json`。设置里的“历史文件位置”配置的是网盘文件夹路径，例如 `/我的应用数据/插件历史/`；界面预览最终文件位置。固定位置 `/dsh-history-plugin/location.json` 保存当前目录指针，新设备先读它，才能自动找到用户修改后的目录。若正式应用的百度授权只允许写应用专属目录，安装时先测试根目录读写；失败则明确提示权限限制，默认改用该应用可写的最外层目录，并在设置页展示实际路径。`deviceId` 是首次运行生成、保存在本机的随机 UUID，不采集硬件序列号；用户可在设置中给它取显示名称。每台设备只写自己的 JSON，读取所有设备 JSON 后合并成一张历史表。这比共写单个 `history.json` 更稳妥：网盘没有供本功能使用的原子比较写入机制，共写可能覆盖另一台设备的新记录。用户看到的是一份统一历史，底层可以是多份很小的 JSON。

```json
{
  "schemaVersion": 1,
  "deviceId": "random-uuid",
  "deviceLabel": "我的笔记本",
  "updatedAt": "2026-10-13T00:00:00.000Z",
  "entries": [
    {
      "eventId": "random-uuid",
      "kind": "installed",
      "key": "registry:dsh-example-plugin@1.2.3",
      "packageName": "dsh-example-plugin",
      "version": "1.2.3",
      "installSpec": "dsh-example-plugin@1.2.3",
      "sourceType": "registry",
      "installedAt": "2026-10-13T00:00:00.000Z",
      "deviceId": "random-uuid"
    }
  ]
}
```

`key` 由规范化来源和版本产生；一次成功安装产生一个安装事件，含 UTC 安装时间与 `deviceId`。同一包在不同设备、不同时间安装的事件都保留，历史页按包聚合并可展开“在哪台设备、何时安装”。事件需有独立 `eventId`，跨设备合并按 `eventId` 去重；重装会产生新事件。从旧配置扫描补录的时间无法证明真实安装日，使用 `observedAt` 和 `kind: "discovered"`，UI 标记“首次发现”，不要伪称安装日期。`deviceLabel` 仅是用户自定义的可选显示名，缺省展示短设备 ID。只存重新安装所需的最小信息和上述设备字段；不写下载路径、完整配置或设备状态。

安装来源必须过滤：registry 包存确定的 `name@version`；Git 地址可保留不含凭据的仓库与固定 ref；带用户信息、令牌、敏感查询参数的 URL 不入云；本机 `file:` / `link:` 路径仅记录包名与版本并标记 `reinstallable=false`，UI 提示需重新提供来源。远端 JSON 一律按不可信输入校验，拒绝超长字段、路径穿越、异常 spec 和未知 schema。

## 4. 同步流程

1. 启动：读取本地历史与待同步队列，按上一节自动查找可复用授权；未授权百度网盘时仍可记录本机安装历史。授权后以百度用户 ID 隔离本地缓存；切换网盘账号时清空当前展示并加载新账号数据，禁止把上一账号记录自动上传到新账号。
2. 首次连接百度网盘：完成 OAuth；获取配置目录的文件列表；逐个拉取 JSON。每份先经大小上限（例如 1 MiB）和 schema 校验，再与本地历史合并。损坏文件跳过并提示，绝不以空记录覆盖。
3. 成功安装：优先使用 plugin-manager 成功结果记录准确 spec/版本，再用 `plugin-manager/changed` + `listBundles` 核对。事件可能漏掉 CLI 或手工更改，启动、重连、打开历史页时再扫描一次；只把新发现的现存外部 bundle 补录一次。安装失败或仅 inspect 不入历史。
4. 本地记录立即可见。后台防抖（例如 3 秒）后，只把**本设备**的累计记录上传到自己的 `<deviceId>.json`。同一设备上传串行化；必须确认同名文件得到更新，不能让 MCP 自动重命名后留下多个版本。MCP 文本上传超限或不能可靠覆盖时切换到开放 API 上传。失败保留待同步标记，指数退避重试。上传成功后再次拉取并合并，避免 UI 陈旧。
5. 下载时流式写入操作系统临时目录。`try/finally` 中关闭流并删除临时 JSON；成功、解析错误、超时和取消都执行清理。临时文件删除失败在下次启动清理本插件命名的过期临时文件。云端历史文件必须保留。内存中只保留有上限的解析结果。

单份 1 MiB 上限用于防异常文件；若未来历史确实超过上限，再设计分页或压缩。为防止大量设备文件导致拉取过慢，列举数量设合理上限并显示诊断。自定义路径须是百度网盘绝对目录且经规范化，不允许 `..` 路径穿越；保存前测试读写，权限不足就保留原目录。日志不得输出 access token、dlink 或含凭据的安装 spec。修改存储目录时提供“迁移现有历史”动作，先验证新目录可读写、复制并核对成功，再更新固定位置的目录指针；其他设备同步前重新读取指针。旧目录清理须单独确认。若根目录无权限且目录指针只能存应用专属目录，使用该专属目录作为固定发现入口。

## 5. 历史页与批量重新安装

**展示页位置（附图 1）：** 左侧点击“插件”后，在主页面标题“插件”下方、现有“官方 8”分类标题同一行增加“历史安装”页签；切换后仍留在插件管理页面。“历史安装”页签展示表格：包名、版本、来源类型、安装时间、设备 ID/显示名、当前设备是否已安装、是否可直接重装；按包聚合，展开可看每次安装事件；支持按时间和设备筛选、搜索、复选、全选可安装项。状态栏显示百度网盘授权、上次同步时间、待同步数量和重试入口。

**设置页位置（附图 2）：** 打开“设置”弹窗，在左侧分类列表中、现有“宠物”项的下方新增独立的“历史插件”项；右侧呈现百度网盘连接/断开与当前账号、已有授权自动检测结果、自动同步状态、默认云端历史目录与“选择/输入网盘文件夹”控件、当前设备 ID/显示名、测试读写、立即同步及存储目录迁移。初始存储位置显示“网盘最外层 /dsh-history-plugin/”，若权限不足显示实际回退目录及原因。凭据由 Host 安全存储管理；设置页只显示授权状态和重新授权按钮，不提供明文 token 输入框或回显。

**DSH 扩展点注意：** 当前公开文档有 `plugins.add.actions` 和详情页插槽，但没有插件主页面“顶部页签”插槽。若目标版本确实如此，需要在 DSH 的 `ui-plugin-manager` 增加一个通用页签扩展点，或由 DSH 官方直接接入此页；不要把所需页签降级成“添加插件”菜单。设置侧已有 `settings.section` 扩展点，可用于独立“历史插件”设置项。

点击“安装所选”先展示确认清单与目标 profile。逐项调用 DSH 的 `inspect(spec)` 检查来源，再串行调用 `installBundle`，展示每项成功、失败、跳过及日志入口。已安装同版本默认跳过；版本冲突、兼容性拒绝、构建脚本批准、需要重启等沿用 DSH 原生流程，不自行绕过。批量任务可停止未开始项；某项失败不阻断后续项。安装结果再次更新历史。只提供“手动确认后批量安装”，不在网盘登录或同步完成时安装。

## 6. 开发顺序与验收

1. **核心服务：** bundle 骨架、百度账号隔离、本地记录、安装事件和启动扫描、JSON schema/去重。验证成功/失败/卸载/账号切换，确认安装时间和设备 ID 正确。
2. **网盘适配：** Desktop 零注册回读、非 Desktop 剪贴板回退、正式 OAuth、MCP 上传、开放 API 下载、临时文件清理、重试和并发设备文件合并。用两个独立 `deviceId` 在同一台设备模拟两台设备，交错上传验证无丢记录。
3. **界面与安装：** 插件页顶部页签、设置独立入口、历史列表、设备筛选、复选确认、逐项安装进度、异常提示。用隔离 profile 验证 registry 包重装、已安装跳过、不可移植来源和部分失败。
4. **端到端验收：** 设备 A 安装插件并自动写入；设备 B 仅用同一百度账号授权后自动看到历史的安装时间和设备 ID；DSH Desktop 中授权页在插件自有 webview 内完成并自动保存，非 Desktop 宿主仍能完成剪贴板回退；已有本插件凭据时启动自动同步，只有浏览器登录态时走 OAuth；选中后确认安装；B 的临时下载文件清理；断网后本地记录可见且恢复网络后自动补传；切换百度账号无串号；根目录可写时使用默认位置，受应用权限限制时明确提示并改用可写目录；自定义云端目录可迁移并让新设备自动发现。

## 7. 已验证事实与待确认项

已在单机实测：百度 MCP 上传 JSON 成功；使用文件元数据取得 `dlink` 后，开放 API 下载 JSON 到本地、解析并逐字节核对成功；测试云文件已删除。百度 `GET /oauth/2.0/device/code` 能返回设备码，但公开演示应用没有可用于换 token 的非空 `client_secret`，因此演示应用不能完成零注册设备码轮询；换成项目方能安全持有密钥的正式应用后，设备码流程可以自动轮询并完成回写。

当前代码已实现 DSH Desktop 自有 webview 读回路径，并保留非 Desktop 剪贴板回退；离线 smoke 覆盖 bridge 版本守卫、partition/lease、导航事件、URL 读回、授权面板层级与挂载点、Escape/Tab 归属、加载失败与超时回退。尚未完成真实 Desktop UI 中的百度登录、授权、自动保存端到端验证。正式产品仍需确认：百度开放平台应用申请及授权方式、正式设备码/回调能力、MCP 服务长期可用性和第三方应用目录权限；DSH 第三方 bundle 能否直接注入 plugin-manager 服务，以及插件主页面页签扩展点的实现方式。
