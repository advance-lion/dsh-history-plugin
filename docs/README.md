# 文档索引与同步规则

仓库内的 `docs/` 是这套插件设计与授权事实的唯一权威副本。仓库外生成的计划稿、
工作目录里的测试记录和对话摘要都只能作为草稿，不能让代码依赖那些路径。

| 文档 | 作用 | 不负责什么 |
| --- | --- | --- |
| `implementation-plan.md` | 产品与工程设计目标、边界、验收条件 | 不描述当前代码已经做到哪一步 |
| `baidu-authorization-chain.md` | 百度体验授权的单机实测链路与正式授权风险 | 不把测试脚本包装成发布版方案 |
| `implementation-status.md` | 当前实现相对设计目标的差异、临时方案和待补验证 | 不替代设计目标本身 |
| 根目录 `README.md` | 使用者当前能看到、能操作到的行为 | 不替代设计目标和实测依据 |

## 维护规则

1. 设计目标变化时，先改 `implementation-plan.md`；不要为了迁就现状去反改目标。
2. 实现行为变化时，同一次提交里至少更新根目录 `README.md` 和
   `implementation-status.md`，并补对应 smoke 断言。
3. 临时授权、演示应用、明文 token、MCP/开放 API 这类事实变化，必须写进
   `implementation-status.md` 的“设计差异”表。
4. 如果代码暂时无法满足设计目标，允许分阶段实现，但差异必须显式记录；禁止用
   README 的措辞掩盖未完成项。
